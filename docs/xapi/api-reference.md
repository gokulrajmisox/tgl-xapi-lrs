# TGL xAPI API reference (implementation status)

Base URL: `/api/xapi/`. Except for `/about`, calls require provider Basic auth and `X-Experience-API-Version: 1.0.0` through `1.0.3`; responses advertise `1.0.3`. Error responses use HTTP status codes and plain-text messages. Statements include `X-Experience-API-Consistent-Through`.

| Resource | Methods currently implemented | Notes |
|---|---|---|
| `/about` | GET, HEAD | Public; reports `1.0.3`. |
| `/statements` | GET, POST, PUT, HEAD | JSON statements/batches up to 100 records; filters include agent, verb, activity, registration, related agents/activities, since, until, limit, ascending, format, continuation, and single-ID retrieval. |
| `/agents` | GET, HEAD | Returns a Person object from stored/requested agent information. |
| `/activities` | GET, HEAD | Returns stored or minimal Activity data for `activityId`. |
| `/activities/state` | GET, POST, PUT, DELETE, HEAD | JSON documents, state list/single document/delete-context, ETag support. |
| `/agents/profile` | GET, POST, PUT, DELETE, HEAD | JSON documents, ETag and conditional write support. Groups are not accepted for agent profiles. |
| `/activities/profile` | GET, POST, PUT, DELETE, HEAD | JSON documents, ETag and conditional write support. |

## Statements

- POST accepts one statement or an array. A provider-supplied `id` is recommended. IDs are generated by TGL when absent.
- PUT requires `statementId`; a body ID, if supplied, must match.
- Same ID/same normalized payload is idempotent. Same ID/different payload returns `409 Conflict`.
- GET by `statementId` excludes voided statements; GET by `voidedStatementId` retrieves a voided target.
- Collection GET returns `{ "statements": [], "more": "" }`; `more` is a signed continuation URL tied to the registration and filters.
- Limit is capped at 1000. `format=ids` returns minimal identifying objects. `format=canonical` is recognized but returns 501 until canonical activity/verb language-map expansion is implemented.
- `attachments=true` and multipart/mixed return `501 Not Implemented`. JSON statement attachments must include `fileUrl`.
- The authenticated provider is recorded as statement authority. A provider needs the `statements.void` scope to submit the reserved voided verb, and may void only statements in its own registration.

## Documents

State and profile endpoints currently accept `application/json` only. `GET` returns ETag and Last-Modified; profile `PUT` requires If-Match or If-None-Match. JSON `POST` performs a shallow object merge. These resources are provider-registration scoped.
